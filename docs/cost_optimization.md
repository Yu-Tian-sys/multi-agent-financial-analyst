# 成本优化

## 背景

一次完整的金融分析流水线原本消耗约 26,688 tokens，成本约 0.027 元。其中 debate 节点占 60-70%，是最大的成本热点。

本文记录三步优化过程和实测数据。

## 成本分解（优化前）

| 部分 | 占比 | 说明 |
|------|------|------|
| debate | 60-70% | 3 轮 × 2 方 + 1 次裁决 = 7 次 LLM 调用，每轮都重复打包财务/新闻/研报 |
| report_writer | ~15% | 1 次长输入 + 长输出 |
| 其他 7 个 Agent | 15-25% | 大部分走 cheap 模型，成本低 |

## 三步优化

### 第 1 步：debate 接入 model_router

**改什么**：debate.py 原本有自己的 `_call_llm` 和 `_client`，改成走 `src/optimization/model_router.py` 的统一入口。

**为什么**：统一基础设施，为后续优化铺路。本身不降本。

### 第 2 步：辩论轮数 3 → 2

**改什么**：`MAX_DEBATE_ROUNDS = 3` → `2`。

**为什么**：减少 2 次 LLM 调用（从 7 次降到 5 次），且 history 累积更短。2 轮 = 双方各 1 次发言 + 1 次反驳，辩论充分性足够。

**预期降本**：15-25%

### 第 3 步：辩论前先总结上下文

**改什么**：在 debate_node 开头加 1 次 LLM 调用，把财务 + 新闻 + 研报压成 200 字摘要。之后所有辩论轮次只发摘要，不再重复传原文。

**为什么**：原本每轮 prompt 都包含完整上下文（约 310 字），5 次调用重复 5 遍。压成摘要后每轮省约 160 字。

**预期降本**：10-15%

## 实测数据

跑 4 次 AAPL 端到端：

| 次数 | tokens | 成本 | 报告长度 | 降幅 |
|------|--------|------|----------|------|
| 改前基准 | 26,688 | 0.027 元 | — | — |
| run1 | 14,291 | 0.0143 元 | 2,733 字 | -46.4% |
| run2 | 14,402 | 0.0144 元 | 2,008 字 | -46.0% |
| run3 | 13,869 | 0.0139 元 | 2,504 字 | -48.0% |
| run4 | 17,633 | — | 1,896 字 | -33.9% |
| **平均** | **15,049** | **0.015 元** | **约 2,400 字** | **-43.6%** |

**波动说明**：run4 高于其他三次（+17%），是 LLM 输出随机性导致。多次取平均才可靠。

## 质量验证

人工审阅优化后的报告全文，检查：

| 检查项 | 结果 |
|--------|------|
| 具体财务数字 | 6 个核心指标全部保留（营收 3832 亿、净利 970 亿、净利率 25.31%、毛利率 46%、ROE 15.6%、负债 2900 亿） |
| 多空观点 | 多头 4 条 + 空头 4 条，均有数据支撑 |
| 风险提示 | 等级"高" + 3 大因素 + 来源标注 |
| 引用来源 | 5 处 |
| 报告结构 | 6 章完整（公司概况/财务分析/市场情绪/多空观点/风险提示/综合结论） |

**结论：优化未导致质量下降。**

## 关键设计决策

### 为什么用总结而不是 system 消息 + prompt caching？

原方案曾考虑把不变上下文放 system 消息，依赖 DeepSeek 的 prefix caching 降价。放弃原因：
- Chat Completions API 无状态，每次调用都要重发所有消息，"只发一次"在 API 层面做不到
- 缓存收益依赖外部条件（TTL、是否命中），不确定
- 总结方案直接在 token 数量上降，收益确定

### 为什么总结用 cheap 模型？

总结是结构化压缩任务（输入已结构化的短文本，输出 200 字摘要），不需要推理能力。cheap 模型（deepseek-chat）足够。

### 为什么辩论从 3 轮减到 2 轮不影响质量？

- 2 轮 = 4 次发言，双方各有 1 次首发 + 1 次反驳，反驳机会完整
- 第 3 轮边际价值递减（通常只是精炼第 1-2 轮观点）
- 实测：2 轮仍产出多空各 4 条论据

### 降级策略

总结失败时（API 异常、超时），`summarize_context` 降级为直接拼接原始上下文，不阻断辩论。保证可用性。

## 下一步优化方向

- report_writer 输入压缩（预期再降 5-10%）
- 语义缓存（相似问题命中缓存，预期降 2-3%）
- 模型路由分层扩展（接入多供应商）
